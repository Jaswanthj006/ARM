The problem

Defects are tiny. Shifts are long.

Too small to see

A broken trace or a hair-thin short is easy to miss at arm's length, board after board.

Tired eyes miss things

Manual checks drift over a shift. Two inspectors can grade the same board differently.

No record, no proof

When a board fails later, nobody can say who checked it, what was found or whether it was fixed.

A phone you own.

Features

Built for the person at the bench.

On device

No cloud. No waiting.

YOLO and Llama run on the phone's Arm CPU through ExecuTorch. The laptop only shows results, so it keeps working when the Wi-Fi to the outside world doesn't.

  • Works in airplane mode
  • Board images never leave the floor
  • One phone per station

Fix advice

Not just what. How.

Every defect card answers three questions: where is it, what is it, and how do I fix it. Llama writes the advice from the detection, in plain language.

  • Location in millimetres from the nearest chip
  • Golden board shown side by side
  • Likely cause, so the process gets fixed too
Review

The operator has the last word.

Confirm a defect or mark it a false call. False calls raise that defect's threshold on the phone, and every decision is saved to retrain the model.

  • One key to confirm, one for false call
  • False call rate tracked per shift
  • Export labelled samples for retraining

Fixed means fixed.

Repaired boards go back under the camera. BoardCheck matches each original defect and shows before and after. Only a clean board is released.

  • New defects from rework are caught

How it works

Everything runs on the phone.

1Camera and QR

The phone reads the board's serial sticker and captures the board.

2YOLO detector

Finds shorts, opens, spurs and more. ExecuTorch, XNNPACK, Arm CPU.

3Llama 3.2 1B

Explains each defect and how to fix it. ExecuTorch, 4-bit, Arm CPU.

4Inspect, then verify

The operator reviews each call, repairs the board and re-scans it.

Technology

Small models, real hardware.

Arm CPU

MediaTek Dimensity 7200 Pro, Cortex-A715 and A510 cores. No NPU or cloud needed.

ExecuTorch

One runtime for both models, with the XNNPACK backend for fast Arm kernels.

Llama 3.2 1B

Instruct model, 4-bit quantised. Turns detections into a decision, cause and fix.

YOLO nano

Trained on the PKU-Market-PCB dataset: six defect classes, tiled for small defects.

FAQ

Good questions.

Does anything go to the internet?

No. The phone runs both models and sends results to the laptop over local Wi-Fi or its own hotspot. You can run the whole demo in airplane mode.

Which phones work?

An Arm-based Android phone with about 6 GB of RAM or more. We build and test on a Dimensity 7200 Pro with 8 GB.

What if the model is wrong?

The operator marks it as a false call. That raises the threshold for that defect on the phone and saves the sample so the model can be retrained.

How does it know which board it is?

The phone reads the QR serial sticker on the board. If a board has no sticker, the operator can type the ID.

Why Llama on a phone?

Detection tells you what is wrong. Llama tells the operator what to do about it, in plain words, without sending data off site.
